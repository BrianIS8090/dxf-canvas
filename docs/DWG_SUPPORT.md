# Просмотр DWG — версия 0.8.0

DWG добавляется той же кнопкой, перетаскиванием или аргументом командной строки, что и DXF. Программа преобразует его во временный ASCII DXF и открывает обычным обработчиком холста. Это импорт для просмотра, не редактор DWG и не отдельная команда экспорта DXF.

## Работа с файлом

- Windows x64: конвертер включён в EXE приложения. Интернет, CAD-система и установленная .NET пользователю не нужны.
- Спиннер показывает этапы «Преобразование DWG → DXF…» и «Чтение преобразованного DXF…». Файлы обрабатываются последовательно в фоне.
- Исходный DWG открывается на чтение. Имя и путь карточки относятся к нему, а не к временному файлу.
- Конвертер и результат создаются в отдельной случайной временной папке. После успеха или ошибки временная папка удаляется. При аварийном завершении приложения она может остаться в системном Temp.
- Дочерний процесс работает без консольного окна; Windows Job Object завершает его при закрытии приложения. Ограничение конвертации — 180 секунд. Это управление временем жизни процесса, не защитная песочница.
- Ошибки и предупреждения не замалчиваются. В карточке файла есть раздел «Предупреждения импорта», с общим числом и первыми 100 подробностями. Предупреждения самой библиотеки пока на английском.

## Движок и лицензии

[ACadSharp 3.7.1](https://github.com/DomCR/ACadSharp) распространяется по [MIT](https://github.com/DomCR/ACadSharp/blob/d7dc111023477d8a9fffc2153139459c95b4f345/LICENSE). Приложение остаётся на Rust; небольшой помощник написан на C# и заранее скомпилирован в машинный код с [NativeAOT](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/). Используются .NET SDK 10.0.302 и runtime/compiler 10.0.10. Отдельный EXE помощника занимает 8 145 408 байт; SDK в поставку не включается.

Версии закреплены в `tools/dwg-converter/packages.lock.json`, исходники помощника доступны рядом. Уведомления ACadSharp, CSUtilities и .NET находятся в `docs/licenses`, встроены в меню версии и собраны в `THIRD-PARTY-LICENSES.txt` при упаковке. LibreDWG и коммерческие инструменты не используются.

## Границы поддержки

- Принимаются заголовки AC1014, AC1015, AC1018, AC1021, AC1024, AC1027 и AC1032 (семейства DWG R14–2018). Наличие заголовка в списке не означает проверку всех файлов каждой версии: контрольный файл — AC1032.
- Отображение результата ограничено [поддержкой DXF](DXF_SUPPORT.md). SHX, пользовательские/прокси-объекты, 3D-тела, растровые изображения, внешние ссылки и листы с VIEWPORT не гарантируются. Внешние чертежи автоматически не подгружаются.
- Чтение выполняется с `Failsafe = false`: ошибки не превращаются в незаметно частичный импорт. Неизвестные объекты запрашиваются с `KeepUnknownEntities = true`, но это не гарантирует их перенос в DXF.
- Библиотека выдаёт предупреждения NativeAOT/trim при сборке. Метаданные ACadSharp сохранены через `TrimmerRootAssembly`; предупреждения не подавлены. Это проверенная реализация для конкретного набора файлов, а не доказательство совместимости всех кодовых путей ACadSharp с NativeAOT.
- Для ответственных измерений и производства сверяйте результат с CAD, особенно при предупреждениях. Отсутствие пропущенных типов в DXF не гарантирует отсутствия потерь на этапе чтения DWG.

## Контрольные проверки

Публичный тест создаёт синтетический DWG: прямоугольник 160 × 100, круглое отверстие, кириллица и слой «Контур». Проверяются импорт встроенным нативным конвертером, геометрия, подпись, слой, этапы загрузки и неизменность исходного файла. Автоматически создаваемый библиотекой VIEWPORT листа отмечается как неподдерживаемый. Повреждённый заголовок отклоняется без изменения источника.

Частный DWG-эталон не публикуется. Его размер 7 750 596 байт, SHA-256 `D96F6FB49D37A27026DC21E1A8E6525F971211C7E85F4A0861FD86DF7140859E`. Парный DXF описан в [матрице DXF](DXF_SUPPORT.md).

После конвертации получены 113 151 геометрический элемент, 337 текстов, 735 заливок и 168 слоёв. Конвертер сообщает 85 предупреждений: в том числе неподдержанные служебные стили, SUN и отсутствующие ссылки на элементы словарей. Ошибок конвертации нет. Эти предупреждения доступны пользователю; результат не объявляется преобразованием без потерь.

```powershell
./scripts/build-dwg-converter.ps1
cargo test --locked
$env:DWG_REFERENCE_FIXTURE = 'C:\путь\к\эталону.dwg'
$env:DXF_REFERENCE_FIXTURE = 'C:\путь\к\эталону.dxf'
cargo test --locked --release reference_dwg_matches_reference_dxf -- --ignored --nocapture
```

Сравнение проверяет единицы измерения, количества элементов, слои с цветами и исходной видимостью, содержимое текстов, габариты, координаты точек отрисовки геометрии и принадлежность/цвет элементов. Для каждого геометрического элемента найдено отдельное соответствие в DXF: координаты точек совпадают с допуском 0,0001 единицы. Разница общего габарита меньше 0,000000001 единицы. Это не попиксельное сравнение с CAD и не проверка всех служебных свойств DWG.

В версии 0.8.0 локально прошли 126 публичных тестов и 4 частные проверки DXF/DWG, кириллицы и виртуального диска; также прошли форматирование и Clippy. Урезанная DXF-сборка проверена отдельно. Парное чтение и сравнение эталонов заняло около 6,7 секунды; это не время до первого кадра окна. Публичная сборка GitHub Actions компилирует конвертер и повторяет обычные тесты без частных файлов.

Проверка также выявила две ошибки отображения, исправленные в 0.7.0: нестабильное число точек дуги при округлении угла и инверсию непрозрачности DXF. Согласно [Autodesk, alpha 255 означает полную непрозрачность](https://help.autodesk.com/cloudhelp/2018/ENU/OARX-RefGuide/files/OREF-AcCmTransparency__setAlpha_Adesk__UInt8.html).

## Кириллица в старом DWG: исправление 0.7.1

На дополнительном частном DWG AC1018 (739 653 байта, SHA-256 `7ABF92C89C1197F57350F30EDCE2A7DABE2377F31AC6563B4390F2664C579FE5`) воспроизведено искажение всех русских названий слоёв. Конвертер записывал корректные байты Windows-1251 и `ansi_1251` в заголовке. Причина находилась в DXF-импорте: основной читатель использовал Windows-1252 по умолчанию, а дополнительный распознавал только верхний регистр `ANSI_1251`.

В 0.7.1 выбор кодировки объединён для обеих частей импорта. Проверены 84 слоя этого DWG, а также синтетические DXF с кириллическими и западноевропейскими именами, вложенными блоками, MTEXT, цветами и заморозкой слоя. Для современных DXF сохраняется UTF-8. Бинарные DXF сохраняют прежние ограничения.

```powershell
$env:DWG_LAYER_FIXTURE = 'C:\путь\к\чертежу-с-84-слоями.dwg'
cargo test --locked bath_hall_dwg_preserves_cyrillic_layers -- --ignored --nocapture
```

## Виртуальные диски: исправление 0.7.2

На подключённом диске O: воспроизведена ошибка Windows 1005. Минимальная проверка показала: обычное чтение DWG работает, `std::path::absolute` работает, а `std::fs::canonicalize` возвращает ошибку файловой системы. Последний вызов был лишним: отдельному процессу нужен абсолютный путь, но не физический путь тома. Он заменён без изменения настройки виртуального диска и без изменения конвертера.

Тест `virtual_drive_dwg_opens_without_modifying_source` проходит реальный импорт и побайтово сравнивает содержимое источника до/после. Он падал с ошибкой 1005 до исправления и прошёл на том же файле после. Локальные файлы сами по себе не воспроизводят особенность драйвера, поэтому тест намеренно отдельный и требует подключённого виртуального диска; в публичном CI не запускается.

```powershell
$env:DWG_VIRTUAL_FIXTURE = 'O:\папка\чертёж.dwg'
cargo test --locked virtual_drive_dwg_opens_without_modifying_source -- --ignored --nocapture
```

Успех этой проверки не гарантирует совместимость со всеми поставщиками виртуальных дисков. Программа не меняет подключения, разрешения или драйверы и не скрывает реальные ошибки чтения.
