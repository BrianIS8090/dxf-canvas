# Подпись Windows

Выпуск 0.9.6 не подписан: у владельца проекта пока нет доверенного сертификата издателя. `SIGNING.json` в выпуске содержит фактический статус Authenticode. SHA-256 проверяет целостность, но не удостоверяет издателя.

Самоподписанные сертификаты не добавляются в доверенные хранилища пользователей. Установщик не меняет настройки SmartScreen и Windows Defender.

## Подключение имеющегося сертификата

Поддерживается сертификат Code Signing в `Cert:\CurrentUser\My` либо `Cert:\LocalMachine\My` с доступным закрытым ключом, включая ключ на токене с установленным провайдером Windows. Нужен SignTool из Windows SDK.

Перед сборкой задайте:

```powershell
$env:DXF_SIGN_CERT_THUMBPRINT = 'ОТПЕЧАТОК_СЕРТИФИКАТА_40_HEX'
$env:DXF_REQUIRE_SIGNING = '1'
# Только если сертификат установлен для компьютера:
$env:DXF_SIGN_MACHINE_STORE = '1'
./scripts/build-dwg-converter.ps1
cargo build --locked --release
./scripts/package-release.ps1
```

`DXF_SIGNTOOL` позволяет задать полный путь к SignTool, если SDK установлен нестандартно. Закрытые ключи, PFX/P12 и пароли не передаются в аргументах и не хранятся в репозитории.

Подпись выполняется по порядку:

1. DWG-конвертер до встраивания в приложение.
2. Переносимый EXE, затем его подписанная копия попадает в установщик.
3. Удалитель и установщик средствами Inno Setup.
4. Проверка цепочки доверия, совпадения издателя и метки времени после каждой подписи.
5. Контрольные суммы окончательных файлов после подписи.

При `DXF_REQUIRE_SIGNING=1` отсутствие сертификата или ошибка подписи останавливает выпуск. Без сертификата обычная сборка явно создаёт неподписанные файлы. Ветка подписи подготовлена, но реальная подпись не проверена без сертификата.

## Выбор сервиса

Для открытого проекта можно проверить участие в [SignPath Foundation](https://signpath.org/). Для собственного сертификата — обратиться к удостоверяющему центру или рассмотреть [Azure Artifact Signing](https://learn.microsoft.com/en-us/azure/artifact-signing/overview), учитывая ограничения регистрации по стране и статусу владельца.

Регистрация издателя и получение сертификата выполняются владельцем. После выбора облачного сервиса потребуется подключить его учётные данные и отдельный шаг подписи в GitHub Actions; текущая схема не изображает такое подключение завершённым.

Подпись подтверждает издателя и целостность, но не гарантирует мгновенного исчезновения всех предупреждений SmartScreen. [Варианты подписи Windows — Microsoft](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options).
