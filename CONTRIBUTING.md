# Участие в разработке

Обсуждение и документация ведутся по-русски. Для исправления ошибки опишите воспроизведение в issue, для новой возможности сначала согласуйте её назначение.

1. Создайте ветку от `main` с понятным именем.
2. Внесите небольшое законченное изменение и добавьте проверки поведения.
3. Выполните `cargo fmt --check`, `cargo test --locked`, `cargo clippy --locked --all-targets -- -D warnings` и `cargo build --locked --release`.
4. Для изменений интерфейса приложите реальные скриншоты на демонстрационных данных.
5. Откройте pull request — предложение изменений для проверки перед включением в основную ветку.

Отступ — 2 пробела, формат задаёт `rustfmt.toml`. Комментарии в коде пишите по-русски. Не включайте в Git `target`, `dist`, секреты, локальные пути и рабочие чертежи заказчиков. Примеры ошибок должны быть минимальными и разрешёнными к публикации.

## Тестовые данные

Публичный набор из 72 тестов не требует внешних файлов: сложные диагностические случаи создаются в `src/test_fixtures.rs`. Оригинальные локальные данные не включены в репозиторий.

Владелец исходного регрессионного чертежа может дополнительно проверить его локально, задав `DXF_PRIVATE_REGRESSION_FIXTURE` с путём к этому конкретному файлу перед `cargo test`. Это не универсальная проверка любого DXF: тесты ожидают фиксированные элементы и 13 замечаний. Не задавайте эту переменную в публичных автоматических проверках.

Для произвольного файла используйте приложение или `cargo run --example inspect_dxf -- "путь-к-файлу.dxf"`.
